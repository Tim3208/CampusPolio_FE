# Google Analytics 방문 분석

## 목적과 현재 상태

2026-11-07 사용자 요청에 따라 CampusPolio의 방문 경로와 이탈률을 분석할 GA4 연결을 추가했다. 사용자가 제공한 운영 측정 ID는 `G-4K84FLPG3F`, 스트림 URL은 [https://campus-polio.vercel.app](https://campus-polio.vercel.app)이다. 코드 연결과 로컬 검증, 운영 설정, 실제 GA4 데이터 수신은 구분해 기록한다.

대상은 루트 레이아웃의 분석 연결, `src/shared/config/analytics.ts`의 환경 설정, `src/shared/lib/analytics/`의 페이지 조회와 URL 정리다. 화면 디자인과 백엔드 API 계약은 변경하지 않는다.

## 1. GA4 웹 스트림 만들기

1. [Google Analytics](https://analytics.google.com/)에 사용할 Google 계정으로 로그인한다.
2. 처음 사용한다면 **측정 시작**에서 계정을 만든다. 기존 계정이 있다면 **관리 → 만들기 → 속성**으로 진행한다.
3. 속성 이름은 `CampusPolio`, 보고 시간대는 대한민국으로 지정한다. 계정 정보와 데이터 공유 선택은 운영자가 실제 조건에 맞게 입력한다.
4. 데이터 수집 플랫폼에서 **웹**을 선택하고 실제 배포 주소와 스트림 이름을 입력한다. 아직 서비스 주소가 없으면 배포 주소가 정해진 뒤 진행한다.
5. 웹 스트림 상세에서 **측정 ID**(`G-...`)를 복사한다. 숫자로 된 속성 ID나 Google 로그인 client ID와 다르다.

[Google의 계정·속성·스트림 생성 안내](https://support.google.com/analytics/answer/9304153?hl=ko)를 기준으로 한다.

## 2. 스트림 설정

**관리 → 데이터 스트림 → 해당 웹 스트림 → 향상된 측정 설정**에서 다음을 적용한다.

| 설정 | 이 구현에서 사용할 값 | 이유 |
|---|---|---|
| 페이지 조회의 고급 설정: 브라우저 방문 기록 이벤트에 따른 페이지 변경 | **끔** | 앱이 최초 진입과 경로 이동을 직접 전송함 |
| 스크롤 | 켬 | 콘텐츠의 90% 지점 도달 측정 |
| 사이트 검색 | 끔 | 검색어를 자동 수집하지 않음 |
| 양식 상호작용 | 끔 | 인증·편집 폼을 자동 분석하지 않음 |
| 이탈 클릭·파일 다운로드·동영상 | 초기에는 끔 | 사용자 입력 외부 링크·파일명 등의 자동 전송 범위를 별도로 결정해야 함 |

자동 조회를 끄는 `send_page_view: false`는 첫 `js` 명령보다 앞선 전역 `set`과 기존 태그 호환용 `config`에 지정한다. 새 Google 태그는 `config`를 기다리지 않고 초기화할 수 있으므로 `config`만으로는 첫 자동 조회가 남을 수 있다. **방문 기록 기반 조회는 GA4 화면에서도 꺼야 한다.** Google Tag Manager나 다른 GA 태그를 추가로 설치하지 않는다. 중복 조회는 참여율·이탈률도 왜곡할 수 있다. 위 설정을 적용한 뒤 측정 ID를 배포 환경에 넣는다.

설정 근거: [수동 페이지 조회와 중복 방지](https://developers.google.com/analytics/devguides/collection/ga4/views), [향상된 측정 항목](https://support.google.com/analytics/answer/9216061?hl=ko).

## 3. 프로젝트와 배포 환경 설정

```dotenv
NEXT_PUBLIC_GA_MEASUREMENT_ID=G-4K84FLPG3F
NEXT_PUBLIC_GA_DEBUG=false
```

위 ID는 CampusPolio 운영 스트림의 공개 설정이다. 배포 서비스의 **운영 빌드 환경변수**에 설정한 뒤 다시 빌드·배포한다. `NEXT_PUBLIC_*` 값은 브라우저 번들에 포함되므로 실행 중인 서버의 환경변수만 바꿔서는 반영되지 않는다. 서비스 계정 키·로그인 비밀키를 넣지 않는다.

- 유효한 ID가 없으면 Google 스크립트와 이벤트 큐를 만들지 않는다.
- 기본적으로 운영 빌드에서만 작동하며 Mock 모드에서는 꺼진다.
- 미리보기 배포에는 운영 ID를 넣지 않는다. `NODE_ENV=production`은 미리보기 빌드에서도 사용될 수 있다.
- 개발·Mock에서 확인하려면 **별도 테스트 스트림 ID**와 `NEXT_PUBLIC_GA_DEBUG=true`를 지정한다. 이 옵션은 실제 테스트 스트림으로 데이터를 보내므로 운영 환경에서는 끈다.
- Storybook은 환경값을 비우고 Google 스크립트를 로컬 mock으로 대체한다. 테스트 스토리는 가상 ID를 사용하며 Google로 전송하지 않는다.

## 수집 범위와 보고서

| 알고 싶은 내용 | 확인할 곳 / 측정 방식 |
|---|---|
| 어디서 유입되는가 | 보고서의 트래픽 획득: 세션 소스/매체, 채널, 캠페인 |
| 첫 방문자는 어디서 오는가 | 사용자 획득: 첫 사용자 소스/매체 |
| 어느 화면을 많이 보는가 | 페이지 및 화면: 페이지 조회·사용자·참여 시간 |
| 어떤 순서로 이동하고 어디서 멈추는가 | 탐색의 경로 탐색: 화면/페이지 경로를 시작점으로 설정 |
| 방문·참여·이탈은 어느 정도인가 | 상세 보고서에 세션·참여율·이탈률 지표 추가 |
| 모바일·PC 등 이용 환경은 어떤가 | 기술 관련 보고서: 기기 카테고리·브라우저 |

GA4 **이탈률**은 참여하지 않은 세션의 비율이다. 기본 참여 기준은 10초 초과, 주요 이벤트 발생, 2회 이상 페이지/화면 조회 중 하나다. 특정 페이지에서 사이트를 떠난 비율과 같은 뜻은 아니다. 화면별 마지막 이동은 경로 탐색으로 함께 확인한다. 보고서에 이탈률이 없다면 편집 권한으로 **보고서 맞춤설정 → 측정항목 → 이탈률**을 추가한다. [GA4 참여율·이탈률 정의와 보고서 편집](https://support.google.com/analytics/answer/12195621?hl=ko)

가입·프로젝트 발행·포트폴리오 제작 완료 같은 비즈니스 이벤트는 이번에 구현하지 않았다. 실제 성공 응답과 연결한 별도 이벤트가 있어야 해당 전환율을 분석할 수 있다. 페이지 조회를 주요 이벤트로 지정하지 않는다.

홍보 링크에는 개인 정보 대신 캠페인 이름을 붙인다. 예: `https://실제서비스주소/?utm_source=instagram&utm_medium=social&utm_campaign=campus_launch`. UTM이 없으면 브라우저가 제공하는 유입 출처를 사용하며, 출처를 제공하지 않는 앱·브라우저에서는 직접 방문으로 표시될 수 있다.

## 전송 규칙

- 첫 화면과 `usePathname`으로 확인된 경로 이동마다 `page_view`를 한 번 전송한다. 뒤로/앞으로 이동도 포함한다. 검색·필터·정렬·페이지 번호·해시만 바꾸는 조작은 별도 페이지 조회로 세지 않는다.
- query는 `utm_source`, `utm_medium`, `utm_campaign`, `utm_id`, `utm_term`, `utm_content`만 허용한다. 100자를 넘거나 `@`·제어문자를 포함한 값은 버린다. 이름 등 모든 개인 정보를 식별하는 필터는 아니므로 UTM에는 운영용 캠페인 값만 넣는다.
- 검색어·태그·`next`·토큰 등의 다른 query와 hash는 전송하지 않는다.
- 포트폴리오 제목에서 생성되는 slug는 `/portfolios/:slug`로 바꾼다. 이 때문에 개별 포트폴리오별 성과는 구분하지 않는다. 숫자 프로젝트 ID는 유지한다.
- 제목은 사용자 입력을 읽지 않고 화면별 고정 제목으로 전송한다. 외부 referrer는 도메인만, 내부 referrer는 정리된 화면 경로만 사용한다.
- `/user-flows`와 알 수 없는 경로는 추적하지 않는다. 기존 태그가 이미 로드된 경우에도 해당 화면에서는 측정을 비활성화한다. 새 라우트를 추가하면 허용 경로도 검토한다.
- 이메일·사용자 ID·프로필·폼 입력을 이벤트에 넣지 않는다. 광고 개인화와 Google signals를 코드에서 끈다. GA 자체의 세션·참여·기기 측정은 사용한다.
- Google 스크립트를 읽는 `afterInteractive` effect보다 먼저 layout effect에서 `set → js → config → event` 큐를 준비한다. 맨 앞의 `set`에 자동 조회 비활성, 광고 비활성, 정리된 페이지 문맥을 함께 넣어 새 태그의 자동 초기화에도 적용한다. [Google 태그 초기화 방식과 config 호환성](https://support.google.com/google-ads/answer/18411054?hl=en)
- 후속 자동 이벤트의 페이지 문맥은 전역 `gtag('set', ...)`으로 갱신하고, 조회 이벤트에도 명시한다. 초기 `config`에 페이지 문맥을 고정하면 전역 값보다 우선하므로 페이지 필드는 넣지 않는다. [Google 태그의 매개변수 우선순위](https://developers.google.com/tag-platform/gtagjs/reference#parameter_precedence)

## 검증

```sh
npm run test:analytics
npx tsc --noEmit --incremental false
npm run lint
npm run test:storybook
npm run build
```

분석 스토리는 실제 컴포넌트를 사용하지만 외부 Google 스크립트를 실행하지 않는다. URL 정리·중복 방지·비활성 상태의 로컬 검사와 실제 Google 수신 확인을 구분한다.

운영 연결 뒤에는 광고 차단이 없는 브라우저로 사이트에 접속하고 **실시간 보고서**, 테스트 스트림에서는 **DebugView**를 확인한다. 홈 → 프로젝트 탐색 → 프로젝트 상세 → 뒤로 이동 시 화면마다 조회가 한 번씩 발생하고 `page_location`과 `page_referrer`가 바뀌어야 한다. 검색·인증 query와 포트폴리오 원문 slug가 전송 값에 없어야 한다. 태그 차단 시 앱은 정상 동작해야 한다. 일반 보고서는 실시간 보고서와 반영 시점이 다르다. PR 검사에 분석 테스트를 추가했으며 원격 CI 결과와 운영 배포 결과는 [PR #32](https://github.com/Tim3208/CampusPolio_FE/pull/32)의 검사·배포 기록과 본문을 따른다.

### 운영 설정 확인

- 웹 스트림 `캠퍼스폴리오 사이트`의 주소와 측정 ID가 사용자 제공값과 일치한다. `CampusPolio` 속성 ID는 `563089680`, 스트림 ID는 `16292222403`이다. 설정 완료 뒤 실제 속성 홈에서 측정 ID를 재확인했다.
- GA4에서 향상된 측정은 켜져 있고 페이지 조회·스크롤만 켜져 있다. 방문 기록 기반 페이지 변경, 이탈 클릭, 사이트 검색, 양식 상호작용, 동영상, 파일 다운로드는 꺼져 있는 것을 확인했다.
- Vercel `tim3208/campus-polio` 프로젝트의 **Production** 환경에 `NEXT_PUBLIC_GA_MEASUREMENT_ID`를 Config 값으로 저장했다. Preview와 Development에는 운영 ID를 추가하지 않았다.
- 무시되는 로컬 `.env.local`에도 ID와 `NEXT_PUBLIC_GA_DEBUG=false`를 저장했다. 개발 모드에서는 기본적으로 수집하지 않는다.
- 환경변수 저장 자체는 운영 코드 배포나 GA4 수신 확인을 의미하지 않는다. 배포 후 실제 사이트 방문과 GA4 실시간 보고서를 함께 확인한다.

### 실제 Google 태그 수신과 초기화 보정

[PR #32](https://github.com/Tim3208/CampusPolio_FE/pull/32)의 원격 검사에서 분석 11/11, Storybook 30파일·310/310, 시각 비교 10파일·12/12, 타입·린트·정적 Storybook·기본 앱 빌드가 통과했다. main `5da9af6`의 [운영 배포](https://vercel.com/tim3208/campus-polio/81S7RhG7iZfr725PSmPHPVP6R2D1)는 2026-11-07 21:38 KST에 Ready가 되었고 실제 `page_view`, `first_visit`, `session_start`, `scroll` 수신을 확인했다. GA4의 **보고서 → 리드 생성 → 트래픽 획득**에는 이탈률 항목을 추가해 저장했다.

실제 SDK 검증에서 전체 페이지 로드마다 기본 제목 `CampusPolio`인 자동 조회가 추가되는 문제를 발견했다. 홈 로드 → 로그인 → 뒤로 → 홈 새로고침의 4회 동작에 수동 조회 4건 외 자동 조회 2건이 더해졌다. 로컬 가상 SDK 검증에서는 드러나지 않은 차이다. 현재 태그의 공개 SDK는 `gtm.init`에서 목적지 태그를 초기화하며, 큐의 첫 `js` 앞에 이 초기화를 넣었다. 기존 `js → set → config` 순서에서는 초기 자동 조회가 뒤의 설정을 읽지 못했다.

자동 조회·광고 비활성 및 페이지 문맥을 담은 전역 `set`을 큐 맨 앞에 옮기고 스크립트 실행 전에 큐가 준비되도록 보정했다. 이후 검증·운영 재배포 결과는 보정 PR의 기록과 함께 확인한다. 배포 확인 중 홈의 프로젝트 조회는 기존 API 오류 상태였으므로 실제 프로젝트 내용의 정상 조회를 검증한 결과와 구분한다.
