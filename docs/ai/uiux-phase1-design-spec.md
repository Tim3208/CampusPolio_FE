## 2. 디자인 방향

- 기존 브랜드를 유지하는 리디자인이다. 로고, Pretendard, 경로, 메뉴 구조는 바꾸지 않는다.
- 차분한 학술 아카이브 톤. 강조색은 하나(`main-10`)만 쓰고 남색 계열 중립색으로 위계를 만든다.
- 모션은 hover·눌림 피드백과 불러오는 중 표시에만 쓰고, `prefers-reduced-motion: reduce`에서는 모두 멈춘다.
- 다크 모드는 1차 범위가 아니다(작업 계획에서 후속으로 분류).

## 3. 색상 토큰

Figma 팔레트는 `src/app/globals.css`의 `main-*`, `gray-*` 토큰과 같다. Tailwind에서는 `bg-main-10`, `text-gray-05`처럼 쓴다.

| 역할 | 토큰 | 값 | 사용처 |
|---|---|---|---|
| 강조 | `main-10` | `#005E9C` | 주요 버튼, 링크, 선택 칩, 체크박스, 현재 페이지 번호, 키보드 포커스 |
| 강조 hover | `main-11` | `#2D77B8` | 주요 버튼 hover |
| 제목·진한 면 | `main-00` | `#001D35` | 제목, 등록 유도 영역 바탕, 코드 블록 바탕, 사진 위 글자 그라데이션 |
| 보조 정보 | `main-12` | `#3D5E7E` | 인용문, 썸네일 없음 문구, 보기 전환 비선택 글자 |
| 입력 테두리 | `main-13` | `#64748B` | 입력창, 정렬 선택, 체크박스 테두리 |
| 강조 테두리 | `main-20` | `#A8CAEE` | 카드·보조 버튼 hover 테두리, 어두운 면 위 포커스 |
| 어두운 면 강조 글자 | `main-21` | `#B6D8FD` | 사진 위 분류 라벨, 코드 키워드 |
| 선택·태그 바탕 | `main-22` | `#DBEAFE` | 태그, 적용된 조건 칩, 마이페이지 현재 메뉴, 공개 배지 |
| 본문 | `gray-01` | `#181C1E` | 본문 |
| 보조 본문 | `gray-03` | `#414750` | 설명, 칩 글자, 메뉴 |
| 메타 | `gray-05` | `#6B7280` | 작성자, 조회·좋아요, 업데이트 시각 |
| 비활성 | `gray-08` | `#A3A3A3` | 비활성 버튼 글자 |

아래 중립값은 시안의 제안이다. ‘현재 코드’는 대응하는 UI 스타일을 가리키며 값이 동일하다는 뜻은 아니다. 예를 들어 `bg-white`와 `surface`의 색상값은 다르다. 기준안 선택 후 기존 전역 토큰에 미치는 영향을 확인해 적용한다.

| 제안 토큰 | 값 | 현재 코드 | 용도 |
|---|---|---|---|
| `canvas` | `#F5F8FB` | 홈·탐색의 `bg-[#F5F8FB]`, `bg-[#f5f8fb]` | 페이지 바탕 |
| `surface` | `#FDFEFF` | `bg-white` | 카드, 패널, 헤더 |
| `line` | `#E3E9F0` | `border-slate-200` | 카드·영역 구분선 |
| `line-strong` | `#CBD6E2` | 없음 | 보조 버튼 테두리 |
| `skeleton` | `#E6EDF4` | 없음 | 불러오는 중 자리 표시 |

`main-01`~`main-05`(Tailwind 파랑 계열)는 대상 화면에서 쓰지 않는다. 강조색이 둘로 보이기 때문이다.

## 4. 글자, 모양, 그림자

**글자** (Pretendard, 이미 전역 로드됨)

| 역할 | 데스크톱 | 모바일 | 굵기 |
|---|---|---|---|
| 상세 제목 | 42px (1024: 36px, 768: 32px) | 26px | 800, 자간 -0.03em |
| 페이지 제목 | 36px | 26px | 800 |
| 섹션 제목 | 28px | 22px | 800 |
| 강조 카드 제목 | 22px | 18px | 800 |
| 카드 제목 | 17px (리스트 카드 15px) | 같음 | 700, 2줄 말줄임 |
| 상세 본문 | 16.5px, 줄간격 1.85 | 15.5px | 400 |
| 기본 글자 | 15px | 15px | 400 |
| 메타 | 13px | 13px | 500~600 |

한국어 제목은 `word-break: keep-all`로 단어가 끊기지 않게 하고, 제목은 `text-wrap: balance`를 쓴다.

**모양** (기존 `--radius: 0.625rem` 체계에 맞춤)

| 대상 | 반경 | Tailwind |
|---|---|---|
| 버튼, 입력, 선택 상자 | 10px | `rounded-lg` |
| 카드, 패널, 상태 상자, 이미지 | 14px | `rounded-xl` |
| 칩, 태그, 배지, 헤더 검색창 | 원형 | `rounded-full` |
| 보기 전환 바깥 / 안쪽 | 12px / 8px | `rounded-xl` 근사 / `rounded-md` |

**그림자**는 남색으로 물들인 값만 쓴다.

- 기본 카드: `0 1px 2px rgb(0 29 53 / .05), 0 8px 24px -14px rgb(0 29 53 / .22)`
- hover·떠 있는 패널: `0 2px 4px rgb(0 29 53 / .06), 0 20px 40px -18px rgb(0 29 53 / .32)`

**아이콘**은 기존 `lucide-react`를 쓰고 `strokeWidth={1.75}`, 기본 18px, 메타 정보 옆은 15px로 맞춘다.

| 태그 | 상세: `main-22` 바탕 + `main-10` 글자 / 카드: `canvas` 바탕 + `line` 테두리 | `Badge` 변형 |
| 상태 배지 | 공개: `main-22` + 지구 아이콘, 비공개: `canvas` + 자물쇠 아이콘 | `Badge` 변형 |
| 체크박스 | 18px, 반경 5px, `main-13` 테두리, 선택 시 `main-10` 바탕 + 흰 체크 | 없음 |
| 일반 카드 | 썸네일 16:10, 분류 라벨 → 제목(2줄) → 설명(2줄, 탐색만) → 태그(1줄) → 작성자 / 조회·좋아요 | 없음 (프로젝트 도메인이므로 shared로 옮기지 않음) |
| 리스트 카드 | 썸네일 112px 폭이 카드 높이를 끝까지 채움, 제목 2줄, 태그 1줄 | 없음 |
| 강조 카드 | 홈 주요 프로젝트. 사진 전체 + 아래쪽 남색 그라데이션, 분류 라벨·제목·작성자·자세히 보기. 카드 전체가 링크 하나 | 없음 |
| 상태 상자 | 아이콘 타일 → 제목 → 이유 한 줄 → 행동 버튼. 빈 상태는 점선, 오류는 실선 테두리 | 없음 |
| 불러오는 중 | 최종 배치와 같은 모양의 회색 자리 표시, 1.4초 주기 깜빡임(감소 설정 시 정지) | 없음 |

**카드 공통 규칙**
- 제목은 2줄까지, 넘치면 말줄임(`line-clamp-2`).
- 태그는 한 줄에 들어가는 것만 보이고, 넘치는 태그는 통째로 숨긴다(`flex-wrap` + 한 줄 높이 + `overflow-hidden`).
- 썸네일이 없거나 불러오기에 실패하면 같은 크기의 `main-22` 바탕에 `image-off` 아이콘과 "썸네일 없음"을 보여준다.
- 결과 개수와 표시 범위 문구("N개 프로젝트", "N개 중 1-9 표시")는 표시하지 않는다.

**포커스**: 밝은 면은 `main-10` 3px 외곽선 + 2~3px 간격, 어두운 면(등록 유도 영역)은 `main-20`.

## 8. 공통 구현 사항 결정

2026-10-04 사용자 결정. 화면 구현의 기준안 선택([설계 문서 안내](README.md))과는 별개다.

1. **`--primary` 색 (결정: 유지)**: 공통 토큰은 현재 `#1E40AF`(main-02)를 유지한다. `Button`·`Badge`의 `default` 변형을 쓰는 로그인 화면, 프로필 설정 폼은 지금 색을 그대로 둔다. 시안의 강조색 `main-10`은 대상 화면(헤더·홈·탐색·상세·마이페이지 틀)에서 클래스로 지정한다.
2. **`--ring` 색 (결정: 적용 완료)**: 회색(`oklch(0.708 0 0)`)이던 라이트 테마 `--ring`을 `var(--main-10)`으로 바꿨다(`src/app/globals.css`). 다크 테마 값은 1차 범위가 아니라 그대로 두었다. `Button`·`Input`의 포커스는 `border-ring`(진한 1px 테두리)과 `ring-ring/50`(반투명 3px 링)을 함께 쓴다. 대비 기준을 채우는 것은 진한 테두리 쪽이고, 반투명 링은 보조 표시다.
3. **버튼 높이 (결정: 새 크기 키 추가, 미적용)**: 기존 크기 키(`default` 32px, `lg` 36px 등)는 그대로 두고 새 키를 추가한다. 로그인·프로필 설정 등 기존 화면의 버튼 크기가 바뀌지 않게 하기 위함이다. 대상 화면은 새 키를 쓰고, 시안의 작은 버튼(36px)은 기존 `lg`를 쓴다.

   | 새 크기 키 | 값 | 용도 |
   |---|---|---|
   | `md` | `h-10 gap-1.5 px-4 text-sm` | 기본 버튼 40px |
   | `xl` | `h-12 gap-2 px-5 text-[15px]` | 큰 버튼 48px, 모바일 주요 버튼 |
   | `icon-md` | `size-10` | 아이콘 버튼 40px |
   | `icon-xl` | `size-12` | 모바일 아이콘 버튼 48px |

   비활성 모양(회색 바탕 + 흐린 글자)은 공통 `disabled:opacity-50`을 바꾸지 않고, 대상 화면 컴포넌트의 `className`으로 지정한다.
4. **Markdown 라이브러리 (결정: 설치 완료, 렌더러 미구현)**: `react-markdown` 10.1.0과 `remark-gfm` 4.0.1을 `dependencies`에 추가했다.
   - **필요한 이유**: 편집기는 본문을 Markdown 글자(`## 제목`, `- 목록`, `**굵게**`)로 저장하는데, 상세 화면은 이를 그대로 출력해 기호가 보인다(T08).
   - **편집기 변환 함수를 쓰지 않는 이유**: 편집기 안의 `markdownToHtml`은 `##` 제목, 목록, 굵게, 기울임, 링크, 이미지만 지원하고 결과가 HTML 문자열이다. 링크 주소도 거르지 않는다.
   - **적용 원칙**: 원시 HTML은 허용하지 않고(`rehype-raw` 미사용), 위험한 URL은 기본 `urlTransform`으로 걸러낸다. 상세 화면은 서버 컴포넌트이므로 서버에서 변환한다.
   - **남은 일**: 렌더러를 구현할 때 실제 버전의 지원 문법과 위험 URL 처리를 검증한다.
   - **보안 점검**: 설치 후 `npm audit`에 두 패키지와 하위 의존성은 나오지 않았다. 기존 의존성(next 등)의 경고는 별도 확인 대상이다.
5. **새 slice·공통 컴포넌트 위치 (결정: 제안대로)**: 7절 표의 위치를 따른다. `src/features/project/project-search-filter/` 신설을 승인받았다.

## 9. 접근성 확인 결과

아래는 기존 시안 문서에 기록된 색상 대비 계산값을 보존한 것이다. 일반 글자는 4.5:1, 테두리·포커스 같은 비텍스트 요소는 3:1을 목표로 삼았다. 이번 문서 리팩토링에서 계산을 다시 수행한 것은 아니며, 표의 통과 표시는 실제 서비스 화면 전체의 접근성 검증 완료를 뜻하지 않는다.

| 메타 `gray-05` / `canvas` | 4.54 | 통과 (여유 적음, 이보다 연한 글자 금지) |

그 밖의 규칙:
- 아이콘만 있는 버튼(검색, 계정 메뉴, 이전/다음, 닫기, 카드 메뉴)은 모두 `aria-label`을 단다.
- 선택 상태는 색만으로 구분하지 않는다. 칩은 바탕 채움, 체크박스는 체크 표시, 메뉴는 바탕과 굵기, 페이지 번호는 바탕 채움과 `aria-current`로 구분한다.
- 마이페이지 메뉴는 페이지 이동이므로 탭 역할 대신 `nav` + `aria-current="page"`를 쓴다.
- 필터 시트는 제목 있는 대화상자로 만든다. 열면 첫 태그로 포커스가 가고, Tab은 시트 안에서만 돌며, Escape로 닫히고, 닫으면 필터 버튼으로 포커스가 돌아간다.
- 불러오는 중 영역은 `aria-busy="true"`와 화면에 보이지 않는 안내 문구를 둔다.

## 10. Figma와 의도적으로 다른 점

| 화면 | Figma | 시안에서 선택한 안 | 이유 |
|---|---|---|---|
| 홈 | "주요 전시", 2행 비대칭 카드 | "주요 프로젝트", 가로 스크롤 한 줄 | 데이터가 인기 프로젝트이고, 카드 수(0~10개)가 바뀌면 비대칭 배치가 깨짐 |
| 홈 | 행사 배너(남은 일수, 등록 인원) | 등록 유도 영역(수치 없음) | Event 기능이 없고, 홈 응답으로 계산한 수를 전체 수로 오해할 수 있음 |
| 홈 | 프로젝트 모음 슬라이더(하단 화살표) | 분야별 칩 + 그리드 + 전체 보기 | 슬라이더 두 개는 중복이고, 칩으로 카테고리 데이터를 활용 |
| 탐색 | 연도·학기·전공 필터 | 숨김 | 결과를 바꾸지 않는 가짜 필터를 노출하지 않음(T09·T10 후속) |
| 탐색 | 첫 카드 2배 크기 | 균일한 카드 | 정렬·검색에 따라 첫 결과가 바뀌어 의미가 없음 |
| 탐색 | 사이드바 하단 설정·고객지원 | 제거 | 누를 수 없는 글자 |
| 탐색 | 설명 문구(기획 메모) | 제거 | 서비스 문구가 아님 |
| 상세 | 지도 교수, 관련 작품 | 표시 안 함 | 제공 데이터 없음 |
| 상세 | 영어 대문자 라벨(AUTHOR 등) | 한국어 라벨 | 한국어 서비스, 날짜는 `createdAt`이라 "등록일" |
| 마이페이지 | 사진 위 공개 배지, "Upload Archive" | 본문 안 배지, "프로젝트 등록" | 사진 위 라벨은 가독성이 떨어짐, 메뉴 이름 한국어 통일 |

**모바일 해석**: Figma에는 모바일 안이 없어 6절 규칙을 새로 정했다. 시안에 기록된 해석은 다음과 같다. 구현에 적용할지는 기준안 선택과 함께 확인한다.
- 모바일 로그인·회원가입 버튼 통합(둘 다 `/login`)
- 모바일 탐색의 "프로젝트 제출" 버튼은 헤더 계정 메뉴의 "프로젝트 등록"으로 대체
- 태그 필터는 하단 시트(적용 전까지 결과 변경 없음)
- 마이페이지 메뉴는 2열 링크
