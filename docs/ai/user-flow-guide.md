# 전체 유저 플로우 검토 화면

## 목적과 확인 방법

사용자 행동과 성공 시 기대 결과를 한눈에 읽고, 필요할 때 조건·예외·구현 근거를 펼쳐보는 검토 화면이다. 기존 기획과 코드를 분석한 목록이며 기능 구현 계획과 현재 사실을 구분한다.

- 앱: 개발 서버에서 `/user-flows`로 접속한다. 예: `http://localhost:3000/user-flows`.
- 이번 작업의 실행 중 미리보기는 짧은 검증용 복사본의 개발 서버 `http://127.0.0.1:3108/user-flows`다. 정적 Storybook `http://127.0.0.1:6008`은 아래 초기 production 검증 시점의 산출물이다.
- Storybook: `Widgets/UserFlows/UserFlowPage/Playground`에서 전체 목록을 자유롭게 조작한다.
- 목록은 정적 데이터로 제공하므로 백엔드 연결이나 앱 Mock 모드가 필요하지 않다.
- 실제 서비스 기능을 대신 실행하는 화면이 아니다. 각 행동의 목표와 현재 구현 범위를 검토한다.

## 확정된 요구사항

- 기존 기획과 코드에서 확인되는 현재·후속 기능을 포함한다.
- 기본 목록은 `사용자 행동 → 성공 시 기대 결과`로 표시한다.
- 구현 상태는 `구현됨`, `미구현`, `확인 필요` 세 가지만 사용하고 일부 구현은 `미구현`으로 표시한다.
- 행동을 펼치면 구현 상태 이유, 기존 또는 제안 상태, 근거 파일을 확인한다.
- 빈 화면·오류·권한 없음·입력·로딩·진행 중 상태를 필요한 항목에 추가한다.
- 로그인·학교 인증·저장·소유권·공개 여부는 `조건별 흐름` 탭에서 관리한다.
- 조건이 있는 행동에는 접힌 상태에서도 해당 조건 링크를 표시하고, 조건에서 관련 행동으로 돌아갈 수 있다.
- 새 아이디어와 아직 확정하지 않은 추가 상태는 `제안`으로 구분한다.
- 탭·아코디언·검색·구현 상태 필터·영역 선택을 직접 조작한다.

## 분석 기준과 범위

2026-10-28 KST에 원본 커밋 `ecd372668b06c788d5dba4b92c1e285e8a23ded4`의 기획과 코드, API 명세를 전체 검토했다. 대부분의 근거 링크는 이 커밋에 고정해 당시 판단을 추적할 수 있다. 2026-11-07 프로필 생성 후 재시도만 수정해 해당 항목의 근거를 수정 커밋 `f7dffd591507e76cfa88853836673aea998191bb`에 별도로 고정했다. 화면의 검토 기준 날짜는 전체 검토 시점을 뜻하며 다른 항목을 전부 재검토했다는 뜻은 아니다.

자료 우선순위는 [설계 문서 안내](README.md)의 확정 상태, [시각·동작 명세](uiux-phase1-design-spec.md), 실제 라우트·기능·API 호출 코드, [API 계약](../../api.md)이다. 명세의 과거 기록을 현재 미구현 증거로 잘못 사용하지 않고 후속 TODO와 현재 코드를 대조했다. Figma와 다른 시안을 새로 선택하지 않았다.

대상 영역은 공통 이동, 로그인·학교 인증, 홈·프로젝트 탐색, 상세·AI 리뷰, 프로젝트 작성·수정, 내 프로젝트, 포트폴리오 제작, 포트폴리오 열람·관리, 프로필, 지원·기획 후속 기능이다. 좋아요 수 표시를 좋아요 추가·취소 구현으로 간주하지 않는다. 개발용 테스트 로그인 API는 사용자용 기능 목록에서 제외한다.

초기 목록은 사용자 행동 **105개**(구현됨 69, 미구현 28, 확인 필요 8), 조건별 흐름 **17개**, 새 아이디어 **6개**다. 숫자는 2026-10-28 분석 결과이며 이후 데이터 갱신 시 함께 점검한다.

| 상태 | 판단 기준 |
|---|---|
| 구현됨 | 해당 문장에 적힌 프론트 화면·행동 처리·필요한 호출 경로를 코드에서 확인했다. 실제 서버의 성공을 의미하지 않는다. |
| 미구현 | 사용자 행동 경로가 없거나 목표 결과의 일부만 연결되었다. UI만 있는 버튼, 로컬 목록만 지우는 삭제, 최종 화면과 다른 완성 미리보기도 여기에 포함한다. |
| 확인 필요 | 코드와 명세의 차이, 명세에 없는 접근 규칙 또는 아직 결정되지 않은 기획 때문에 목표 결과를 확정할 수 없다. |

기존 예외 상태는 구현된 안내와 제한을 설명한다. `제안` 예외 상태는 추가로 필요한 UX 후보이며 정책을 확정하거나 제품 코드를 변경하지 않는다. API 계약만 있는 권한 규칙은 조건 탭에서 계약 근거임을 설명하며 실제 서버 검증과 구분한다.

### 주요 판단 사례

- 로그아웃·탈퇴·포트폴리오 공개 변경·기존 편집·삭제: 계약은 있지만 사용자 UI가 없으므로 미구현이다.
- 프로젝트 연도·학기·전공: 폼 선택은 있지만 저장 payload가 없어 미구현이다.
- 프로젝트 신규 공개 등록·수정 완료: 현재 목적지는 상세가 아닌 내 프로젝트 모음이다.
- 임시저장 프로젝트 재개 후 발행: 수정 경로는 PATCH만 하므로 미구현이다.
- 프로젝트 파일 제거와 기존 첨부 불러오기: 화면 목록 제거와 서버 DELETE·기존 파일 조회 연결을 구분한다.
- 내 프로젝트 상태·페이지: 프론트 조회 옵션은 있지만 명세는 배열 응답이고 query 조건이 없어 서버 지원은 확인이 필요하다.
- 포트폴리오 제작 목록: 첫 8개의 로컬 검색은 구현되었고 다른 페이지 탐색과 정렬은 미구현이다.
- 포트폴리오 썸네일: 로컬 미리보기만 구현되었다. 저장에는 선택 순서 중 썸네일이 있는 첫 프로젝트의 이미지를 사용한다.
- 프로필·포트폴리오 저장: 명세 필수 `userId` query와 현재 세션 전제 호출의 차이가 있어 확인 필요다.
- 학교 인증: 화면 문구의 학교 범위와 `.ac.kr` 검사 차이, 실제 SMTP 대신 서버 로그를 명시한 발송 계약은 확인 필요다.
- AI 리뷰 권한·코드 존재·횟수 제한과 Draft 상세의 본인·타인 접근은 명세가 불명확하므로 새 정책을 만들지 않았다.
- Event·전시의 진입·범위는 기획 후속 결정 사항이며 구현된 기능으로 간주하지 않는다.

새 행동을 추가할 때 영역, 고유 ID, 기대 결과, 세 가지 구현 상태, 판단 이유와 실제 존재하는 근거 파일·줄을 기록한다. 조건 ID는 조건 목록에 존재해야 하며 관련 행동은 연결 관계에서 자동 계산한다. 기존 기획에 없는 기능은 아이디어 목록으로 넣는다. 상태와 항목 수는 데이터에서 계산되며 코드 변경을 자동 감시해 구현 상태를 바꾸지는 않는다.

주소의 `#actions/행동ID`, `#conditions/조건ID`, `#ideas/아이디어ID`로 특정 항목을 열 수 있다. 조건 링크 이동 시 검색·필터를 해제해 연결 항목이 숨겨지지 않게 하고 초점을 이동한다. 브라우저 뒤로·앞으로·새로고침으로 탭과 연결 항목을 복원한다.

### 2026-10-28 — 사용자 코멘트에 따른 화면 간소화

사용자가 지목한 제목 위 영문 문구, 제목 아래 설명, 표기 기준 안내, 사용자 행동 탭의 결과 수와 설명 행을 제거했다. 결과 수는 화면 낭독기를 위한 안내로만 유지한다. 조건별 흐름과 새 아이디어 탭의 기존 결과 안내는 그대로다.

짧은 복사본에서 타입 검사와 변경 UI 린트, 전체 Storybook 29개 파일·283개 테스트가 통과했다. 실제 앱의 데스크톱 화면과 Storybook Playground의 데스크톱·360px 화면에서 변경을 확인했다. 갱신된 production 빌드는 실행 중 중단했으므로 성공으로 기록하지 않으며, 현재 3108 미리보기는 webpack 개발 서버다. 기존 시각 비교 대상은 영향을 받지 않아 `test:visual`은 실행하지 않았다.
